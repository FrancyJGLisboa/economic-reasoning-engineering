# Faithful extraction default

## Outcome

Preserve the documented context and judgment of source speakers without improving their methods during extraction.
The user still invokes the skill and supplies material. Critique requires an explicit request.
Keep the current economics and operations profiles. Broader domain routing is outside this change.

## Contract and ownership

The primary agent owns instructions, schemas, packaging, tests, and private source verification.
New runs declare `extraction_mode` as `faithful` or `faithful_with_critique`.
The second mode records the user's request in `critique_authorization`.
Documented methods identify the speaker and link each step to stated or demonstrated source evidence.
Missing steps and decision criteria remain missing. Incomplete documented methods are valid fragments.
Optional critique uses a separate indexed artifact. It cannot replace the documented method.
Legacy runs remain readable without invented mode or provenance metadata.

## Acceptance criteria

1. Instructions remove mandatory method improvement, arithmetic correction, and hypothetical transfer probes from default extraction.
2. New faithful methods require source attribution and resolvable step evidence indexes.
3. Optional critique requires explicit authorization and remains separately navigable after relocation.
4. Existing package tests pass. Invalid modes, mixed metadata, unauthorized critique, and unsupported step declarations fail.
5. A private real-source trial preserves source arithmetic and documented steps without adding corrected procedures.

## Challenge reviews

Executability: optional metadata and one optional collection fit the existing builder and bundled reader.
Failure review: exact anchors do not prove entailment. Tests must state that semantic fidelity remains unverified.
Failure review: requiring complete methods encourages invention. Accept documented fragments and explicit NOT_DOCUMENTED fields.
Failure review: a new label must not relabel old investigator proposals as documented speaker methods.
Failure review: critique authorization is a recorded declaration. Code cannot prove the agent received that user request.

## Excluded work

Do not claim identical persona behavior, independent evaluation, human approval, or empirical method quality.
Do not publish private transcripts. Do not change selective reading, add dependencies, or add a runner.
