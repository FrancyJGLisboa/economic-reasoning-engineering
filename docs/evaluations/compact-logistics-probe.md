# Compact retrieval: logistics follow-up

## Scope

This experiment follows the [first logistics rule probe](logistics-rule-probe.md).
It tests lower input consumption while preserving a documented method, source access, and synthetic case conclusions.
The same three case texts remain unchanged. This is not a new personal-judgment test.

The answer schema now defines delivery duration and deadline slack separately.
All conditions use the revised schema. Numeric results are compared within this batch, not against the earlier ambiguous field.

## Changes and acceptance

The compact helper retains selected records, parent episodes, related data gaps, and scoped state.
It replaces repeated record references with ordered identifiers into a shared reference table.
The table contains source, timestamp, snapshot path, and line. Full referenced snapshots appear once.
Source words are unchanged. Repeated anchor quotes and locator prose are omitted from the evaluated payload.
Method steps retain their reference-index order. Investigator proposals retain their classification.
Internal projection checks restore original record references from the package and compare original fields and order.
This restoration uses the original package. The compact model payload is not a replacement portable package format.

Acceptance requires correct case status, delivery duration, and slack for every response.
Checks also require complete runtime output, unchanged cases and sources, exact available citations, and lower total input to establish savings.
Model-selector input and output count toward consumption. No monetary cost is inferred.
Independent human review remains pending. Stable skill behavior remains unchanged.

## Frozen comparison

Each condition runs twice. The order is raw text, model selection, lexical selection, lexical selection, model selection, raw text.
The raw condition receives all eight eligible source snapshots.
The model-selected condition uses a compact index followed by one answer session with retrieved context.
The lexical condition uses a deterministic method lookup followed by one answer session.

The lexical lookup ranks method titles and triggers by overlap of normalized five-character word prefixes.
It takes the first two positive matches. It contains no hardcoded method identifiers or case answers.
This route changes selection as well as token overhead. It must not be presented as a pure compaction effect.
Method-only lexical lookup does not establish general semantic retrieval across domains.

The investigator freezes case facts, rubric, schemas, helper, runtime, and package hashes before execution.
The investigator knows the rule and case answers. No independent quality or persona claim follows from this sample.
The evaluated models have no external tools or search.

## Results

All conditions match the expected status, delivery duration, and deadline slack on all six case responses.
These are three synthetic scenarios repeated twice, not six independent historical judgments.

| Condition | Status /6 | Duration /6 | Slack /6 | Total input | Total output |
|---|---:|---:|---:|---:|---:|
| Complete raw text | 6 | 6 | 6 | 60,302 | 2,365 |
| Compact, model-selected | 6 | 6 | 6 | 88,542 | 2,722 |
| Compact, lexical-selected | 6 | 6 | 6 | 47,664 | 2,435 |

Totals include both repeats and any model-selection calls.
Lexical selection reduces input by 20.96% against same-batch raw text. Output is slightly higher.
Model selection increases total input by 46.83% against raw text.
These token totals do not establish monetary savings.

The model-selected answer sessions use 23,654 and 23,740 input tokens, a combined 21.41% reduction from the raw answer sessions.
Each selector adds 20,574 input tokens. Compaction lowers answer context while the separate selector prevents total savings.
The lexical route avoids a model-selection call. Its total savings combine compaction with a different routing mechanism.

Both model selectors choose the import-clock and purchase-timing methods.
One also chooses a fidelity review, without adding another source snapshot.
Lexical selection chooses the import-clock method and the weakly relevant delivered-cost method.
The purchase-timing method ties with the cost method and loses the identifier tie-break.
This observed routing error prevents a general retrieval-quality claim despite correct final case answers.
One response explicitly states that the cost method does not supply delivery durations.

All ten raw citations, nine model-selected citations, and eight lexical-selected citations match exact words at available source timestamps.
Investigator review finds that explanations keep synthetic calculations separate from source examples and retain unknown durations.
That review is not independent human assessment.

## Verification and remaining limits

Frozen-input, source-identity, case-identity, projection, runtime, and answer-completeness checks pass.
Negative integrity tests reject changed facts, missing answers, modified responses, and modified retrieved payloads.
Helper tests reject empty, unknown, or duplicate selections, no-match queries, and altered evidence.
These checks establish artifact integrity and defined case behavior, not general semantic fidelity.

The earlier baseline already solves these simple cases without personal context.
This batch does not establish incremental judgment transfer, equivalent persona, or noninferiority across domains.
Independent human review remains pending. Stable skill behavior remains unchanged.
Next acceptance work must test retrieval on different questions, including omissions, before any stable promotion.
